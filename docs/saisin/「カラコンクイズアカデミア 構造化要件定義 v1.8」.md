## ★★★ 現在の状況と調査経緯 (v1.8追記) ★★★

### 発生している問題

Webアプリを実行すると、サーバーサイドで以下のエラーが発生し、クイズが生成されない。
`Error: 問題の生成中にサーバーでエラーが発生しました: クイズを作成するのに十分なデータがありません（最低4件必要です）。`

### ユーザーの分析

ユーザー自身でスプレッドシートを確認したところ、クイズ生成の条件（必須項目が埋まっており、カテゴリシートと情報が一致する）を満たすデータが900件以上存在するはず、との報告。プログラムの挙動と矛盾が発生している。

### これまでの調査経緯

1.  **ロジックの確認:** クイズ生成ロジック（`DataAccess.gs`内）を確認。商品データは①必須項目（ブランド、カラー、レンズ画像URL）が全て存在し、かつ②その「ブランド｜カラー」のキーが`カラーカテゴリ`シートに存在する場合にのみ「有効な候補」となる仕様。ロジック自体に問題は見当たらなかった。
2.  **データ不整合の調査:** 当初、2つのシート間でデータ（ブランド名・カラー名）の不一致や、目に見えない空白（スペース）が原因と推測したが、ユーザーによるデータ修正後も問題は解消せず。
3.  **設定ファイルの確認:** `Config.gs`を確認し、プログラムが参照している列定義（I列、J列、X列など）が想定と一致していることを確認。
4.  **スプレッドシートIDの不一致:** `Config.gs`に設定されていた`MASTER`シートのIDが、ユーザーが実際に編集していたシートのIDと異なっていることが判明。これを正しいIDに修正したが、エラーは解消されなかった。

### 現在の対応と次のステップ

原因が特定できないため、**プログラムが実際にどのデータをどのように処理しているか**を可視化するアプローチに切り替えました。

1.  **デバッグ関数の追加:** `DataAccess.gs`に、データの処理状況を詳細に記録・報告する`debugDataProcessing`関数を追加済み。
2.  **フロントエンドの修正:** `index.html`を修正し、「練習モード」ボタンを押すと、通常のクイズ生成の代わりに上記のデバッグ関数が実行され、結果が画面に表示されるように変更済み。

**【最重要】次に行うべきこと:**

1.  **`clasp push`を実行**し、ここまでの修正（デバッグ関数の追加等）をGoogle Apps Scriptサーバーに反映する。
2.  Webアプリをリロードし、**「練習モード」ボタンをクリック**する。
3.  画面に表示される**「デバッグレポート」の内容をすべてコピー**し、次の会話でAIエージェントに渡す。

これにより、エラーの根本原因が完全に特定できる見込みです。

### 完了した副次タスク

*   ブラウザのデベロッパーコンソールに表示されていた`window.alert`の非推奨警告は、ネイティブなアラートをカスタムUIダイアログに置き換えることで解決済み。

## 0. 変更概要（v1.6.1 → v1.7 差分まとめ）

* **画像取り扱いの厳格化**

  * マスタ `W列=サムネ`, `X列=レンズ` の役割を明確化し、**クイズ画面はレンズ画像（X列）を参照**。Wは正解フィードバック時のサムネ表示に使用（v1.6.1の「正解時: サムネ画像表示」を運用確定）｡
  * **GitHub直配信**を前提に、**Drive→GitHub 日次同期**＋**クイズ時のURL動的生成**の二段フローを正式採用（CDN不要）。
  * **命名規則の更新**：**K列（装用期間）を必須でファイル名に含める**（一意性担保）。例：`品番_ブランド_カラー_1day_lens.jpg`。

* **スコアリング/進行の運用確定（v1.6.1の追加仕様を明文化）**

  * **タイムアウト＝未回答**として次へ（-10%扱い相当）／**正解時のフィードバックは2秒表示後に自動遷移**。**出題対象はデータ完備商品のみ**。**重複ログインは最新セッション優先**。

* **ランキング / マイ成績のAPIコントラクトを採用**

  * `GET ?action=ranking&scope=daily|weekly|monthly`、`GET ?action=mystats&user=...`、`POST action=submit` の**GAS Web API**仕様を要件化。履歴は `quiz_history` に追記。

* **UI/UX 更新の採用**

  * デモHTMLの画面骨子（ログイン/ホーム/クイズ/結果/ランキング）と**配色・動線**をガイドラインとして確定。フォントは**Noto Sans JP**（グラフや可視化も含め必須）。

* **権限と運用前提の明示**

  * Driveは**指定者のみ閲覧権限（変更不可）**、バッチは**サービスアカウント read-only**で同期、**GitHubへは編集権限付与**。

### 3.2 カラーカテゴリ

## 4. 画像同期と参照（運用要件）

### 4.1 日次同期（GitHub Actions or 外部ツール）

* Drive の元画像を\*\*日次（JST 2:00）\*\*で GitHub `images/_lensimage/` へ同期（**差分追加のみ**）。
* サービスアカウントに **対象シート/Driveフォルダの閲覧権限（read-only）** を付与。
* ファイル名生成：**G=品番, I=ブランド, J=カラー, K=装用期間**＋画像タイプ（lens/samune）。
* 既存ならスキップ／新規はコミット。失敗はログ化。

> **権限前提**：Driveは**指定者のみ**・権限変更不可。GitHubには編集権限を付与。

### 4.2 クイズ時の参照

* サーバ（GAS）が**I+J（＋K）をサニタイズ**して GitHub `raw` のURLを**動的生成**し、フロントへ返却。
* 取得はGASプロキシ `getGitHubImageAsBase64` 経由。**エラー時はplaceholder**で止めない。
* raw取得失敗時は **jsDelivr** にフェイルオーバーして可用性確保（UI側）。

## 5. クイズ仕様（確定）

* **認証**：スタッフ番号＋名前（暫定）。
* **モード**：本番（1日1回）／練習（無制限・任意回）。
* **問題数**：10問固定、**制限時間 20秒/問**。
* **出題**：**データ完備**の商品からランダム。誤答3件はカテゴリ一致などの条件で抽出。
* **ヒント**：①DIA/G.DIA/BC、②コメント。各使用で **-3%** 加点減。
* **スコア**：`100% - (不正解×10%) - (ヒント×3%)`（下限0%）。
* **タイムアウト**：未回答扱いで次へ（-10%相当）。
* **正解フィードバック**：**2秒表示→自動遷移**。
* **正解時サムネ表示**（W列画像）。
* **重複ログイン**：**最新セッション優先**。

> **UI骨子**は現行デモHTMLの構成を採用（ログイン→ホーム→クイズ→結果→ランキング/マイ成績）。

## 6. ランキング / マイ成績（API契約）

### 6.1 API（GAS Webアプリ）

* **GET** `?action=items` … 10件の出題候補（brand, color, images, specs 等）
* **POST** `{action:'submit', user, store, score, correct, total, accuracy, timeSec, hints, dateISO}` … 履歴保存
* **GET** `?action=ranking&scope=daily|weekly|monthly` … 期間別ランキング（points合計/正答率mean等）
* **GET** `?action=mystats&user=...` … 直近10回＋通算サマリ（played, points, accuracy, avgTime）
  **レスポンス例・実装サンプル**は添付実装案どおり。シート `quiz_history` は**追記のみ**。

### 6.2 表示仕様

* **ランキング**：日/週/月タブ切替。自分の行はハイライト。
* **マイ成績**：**直近10回のポイント棒＋正答率折れ線**をCanvas描画（外部ライブラリ不要）。
* **Noto Sans JP を全画面で適用**（文字化け回避）。

## 8. 非機能要件 / 例外時動作

* **可用性**：画像は **raw → jsDelivr** の順で自動フォールバック。読み込み不可時は**パターン表示**で継続。
* **エラー耐性**：**「止めない」設計**（フォールバック必須／ログ出力）。
* **権限**：Driveは指定者のみ/変更不可、サービスアカウントはread-only、GitHubは編集権。
* **パフォーマンス**：画像は必要最小サイズ（Web向け）で同期。必要なら段階的にWebP化（オプション）。

## 11. geminicli 実行用タスク指示（最短）
